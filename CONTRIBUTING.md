# Contributing

Thanks for helping improve mrcakes931-ecosystem.

## Before opening a change
1. Read README.md, AGENTS.md, manifest.json, and SECURITY.md.
2. Check the master registry for dependencies and related contracts.
3. Open or reference an issue for substantial work.
4. Keep changes within this repository's stated ownership boundaries.

## Pull requests
- Explain the problem, proposed change, and affected requirements.
- Include tests, fixtures, or validation evidence for behavior changes.
- Update documentation, examples, manifest, compatibility notes, and CHANGELOG.md as needed.
- Identify breaking changes and migration steps.
- Never include secrets, private data, or unlicensed third-party material.

## Standards
Prefer established standards and interoperable formats. Security-sensitive changes require explicit threat analysis and review. Do not mark a capability implemented until its tests and evidence exist.
